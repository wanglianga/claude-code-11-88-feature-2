# 科研影像湖仓存储治理平台（Research Imaging Lakehouse Governance）

面向科研影像湖仓的存储治理平台，覆盖**对象目录、血缘 DAG、保留策略、恢复校验、成本分摊、归档快照、项目审阅**七大能力，并提供**共享影像湖仓账单双路线分摊工作台**（有效引用权重 / Shapley 边际成本）。
技术栈：**Vue 3 + Vite + Pinia**（前端）、**Spring Boot 3 + Spring JDBC**（后端）、**PostgreSQL 18**（数据库，递归 CTE 实现血缘闭包与影响传播）。

## 1. 业务能力与题目对应

| 题目要求 | 实现位置 |
| --- | --- |
| 对象目录：对象ID/字节数/校验摘要/层/创建访问时间/责任项目/保留截止日 | `data_object` 表 + 「对象目录与分层」界面 |
| 血缘 DAG：输入输出方向、版本、处理配方、共享引用 | `lineage_edge` 表 + 递归 CTE（`LineageService`）+ SVG DAG 界面 |
| 保留策略：按类别×协议算最早可删除日；源未到期/冻结时派生物不得先销毁 | `retention_policy` + `RetentionService.recalculate`（祖先截止日传播） |
| 算法包/校准证据至少保留到最后依赖结果期限届满 | 同上，对 `SOFTWARE_PACKAGE`/`CALIBRATION` 做下游期限延展 |
| 恢复计划：沿血缘反向求依赖闭包，核对摘要/软件包/目录可用性 | `RestoreService.createPlan` |
| 4 小时 RTO、提前 72h 预约；缺件/超时启动前标记不可满足并列缺项 | 计划状态 `SATISFIABLE/UNSATISFIABLE`，执行阻断返回 409 |
| 只迁移结果无算法包，哈希通过也不可宣称复现 | 闭包缺 `SOFTWARE_PACKAGE` 即判缺件 |
| 两路线：预约分层 DAG 预取 vs 可校验恢复包（4h RTO 层） | `SCHEDULED_TIERING` / `RESTORE_PACKAGE` 双策略 + 盈亏平衡频次 |
| 成本账：日字节时长×层费率、取回费、恢复计算费 | `cost_daily`、`retrieval_event`、`CostService` |
| 独占归项目、共享按冻结引用/使用份额分摊，分摊总额=月账单 | `object_share` + `monthly_bill.allocation_check` 核对 |
| 共享影像湖仓账单：对象-项目成员快照、字节时长、读取量、专属资源账与对账约束 | `membership_snapshot`/`byte_hour_ledger`/`read_usage_ledger`/`exclusive_resource_ledger`/`share_reconciliation` |
| 双路线分摊共享对象费：有效引用权重（3:1→7.50/2.50）与 Shapley 边际成本（各 5.00），两路线均合计 19 元 | `ShareAllocationService` + 「共享账单双路线分摊」界面 |
| 撤销末次引用本月快照不变、下一周期按新成员集重算 | `membership_change` 流水 + 账期快照冻结（出账不可变） |
| 归档快照：目录水位+依赖+费率版本，可回放迁移/保留/计费理由 | `archive_snapshot` + 「归档快照回放」界面 |
| 项目退出后共享对象仍被引用不得整体删除 | `ProjectService.withdraw` → `BLOCKED_SHARED_REFERENCE` |
| 校验失败/规则变化/争议冻结传播到所有依赖结果并保留原归档决定 | `governance_event` + 正向影响传播；快照不可变 |

## 6. 验证方式

### 6.1 自动化端到端验证（推荐）

后端启动后执行：

```bash
python3 scripts/verify_e2e.py
```

脚本覆盖 80 项断言，包括：

1. 研究 A 数据量（原始 2TB、标注 80GB、校准 12GB、掩膜 200GB、特征 5GB、结果 1GB）与 sha256 摘要；
2. `RESULT-A01` 反向依赖闭包 = 7 个对象（含校准与算法包），深度正确；
3. 原始影像保留 10 年（2036-01-15）；算法包/校准延展到最后依赖结果期限；
4. 争议冻结、校验失败沿血缘传播到全部下游结果；
5. 年 1 次预约计划：72h 提前量、3h 预计恢复 ≤ 4h RTO、闭包 7 对象；
6. 月账单存储费手工口径核对、共享份额（掩膜 70/30、算法包 60/40）、`allocationCheck=true`；
7. 执行恢复后取回费/恢复计算费入账；
8. **年 1 次时预约分层更省；月 1 次时恢复包更省**，输出盈亏平衡频次（约 3.83 次/年）；
9. 故意移除校准文件 → 计划 `UNSATISFIABLE`、执行 409 阻断、恢复包校验失败；恢复后复原；
10. 移除算法包 → 即使哈希通过也判定不可复现；
11. 研究 A 退出 → 共享掩膜/算法包被研究 B 引用保护，不得整体删除；
12. 归档快照固定目录水位/9 条血缘边/费率版本，并可回放全部治理决定；
13. **共享影像湖仓账单双路线分摊**：总额 19 元、两路线对账通过；引用权重 A 12.90/B 6.10、Shapley A 10.40/B 8.60；字节时长账 90 行且 O1 月费精确 10 元；撤销 B 末次引用后本月不变、下月 O1 全归 A；恢复引用在新账期按新成员集重算，已出账期快照不可变；读取量按项目直接归属。

### 6.2 界面手工验证路径

1. 登录后进入「恢复计划与校验」，点击「移除/恢复校准文件 CAL-A01」→「创建计划并检查」，观察红色 `UNSATISFIABLE` 与缺项清单，执行按钮禁用；
2. 恢复校准后创建 `RESTORE_PACKAGE` 路线、年频次 12 的计划，观察可满足；
3. 「成本账与分摊」生成 2026-11 账单，观察两项目费用、共享份额标签与分摊核对标签；对比表展示年 1 次/季 1 次/月 1 次的两路线费用；
4. 「**共享账单双路线分摊**」生成 2026-11 账单，切换「有效引用权重 / Shapley 边际成本」页签观察 A/B 项目账单与 O1 对象级权重、平均边际成本；在成员快照区撤销 PROJ-B 对 O1 的引用后重算 2026-11（不变），再生成 2026-12 观察 O1 全部 10 元归 A；点「重置为题设初始状态」可一键复原；
5. 「保留策略与传播」对 `RAW-IMG-A01` 点「争议冻结」，观察下游 `RESULT-A01` 同步变为冻结阻断；
6. 「项目审阅」对 PROJ-A 点「项目退出」，观察共享对象保护清单；
7. 「归档快照回放」生成快照并切换页签回放当时的保留/冻结/迁移/退出决定。

## 7. 计费口径与样例数值（费率版本 RV-2026Q4）

- 计量：1 GB = 10⁹ 字节；月按 30 天；日存储费 = GB × 层 GB·月费率 / 30。
- 研究 A 完整闭包单次按需恢复（年 1 次场景）：取回费约 **¥12.16** + 恢复计算费约 **¥4.98** = **¥17.14/次**。
- 30GB 恢复包驻留 RESTORE_TIER（¥0.18/GB·月）：月费 **¥5.40**，年费 **¥64.80**。
- 盈亏平衡：当年频次 > 约 **3.83 次/年** 时，恢复包路线的额外占用成本低于重复取回成本；即题设年 1 次预约取回更省，改为月 1 次后恢复包更省。
- 全部费率集中在 `storage_tier` 表，调整后重新生成账单即可，快照会固化当时费率版本。

### 7.1 共享影像湖仓账单样例（场景 SCEN-IMGLAKE，费率版本 RV-2026Q4）

题设月度账单（存储费 0.10 元/GB·月、读取服务费 0.02 元/GB，1GB=10⁹B、月=30 天）：

| 费用项 | 计算 | 金额 |
| --- | --- | --- |
| 共享源影像 O1 | 100GB × 0.10 | ¥10.00 |
| 项目A 专属派生 DERIV-A | 30GB × 0.10 | ¥3.00 |
| 项目B 专属派生 DERIV-B | 20GB × 0.10 | ¥2.00 |
| A 读取服务费 | 120GB × 0.02 | ¥2.40 |
| B 读取服务费 | 80GB × 0.02 | ¥1.60 |
| **账单总额** | | **¥19.00** |

O1 被 A 的 3 个、B 的 1 个有效研究分支引用，两条分摊路线（专属费与读取费均直接归属，不参与分摊）：

| 路线 | O1 分摊口径 | A 分摊 | B 分摊 | A 合计 | B 合计 |
| --- | --- | --- | --- | --- | --- |
| 有效引用权重 | 按分支权重 3:1 | ¥7.50 | ¥2.50 | **¥12.90** | **¥6.10** |
| Shapley 边际成本 | 排列枚举平均边际；联盟非空即发生全部费用，移除单项目省不下 ¥10 | ¥5.00 | ¥5.00 | **¥10.40** | **¥8.60** |

两条路线项目合计都严格等于 ¥19.00（`share_reconciliation.reconciled` 逐路线核对）。
Shapley 实现对成员全排列（n!）枚举边际成本：两成员联盟中每个项目仅在排列首位时产生 ¥10 边际，平均后各 ¥5.00，体现“不可避免的共享基础成本”；权重路线简单可复算，但多分支项目承担较多。

**跨周期规则**：撤销 B 的最后一个引用只登记 `membership_change` 并自下一账期生效，本月已冻结的 `membership_snapshot` 与账单不变；下一周期 O1 仅属 A，由 A 承担全部 ¥10.00、B 不再分摊（B 仅剩专属 ¥2.00）；若之后仍有其他项目引用，则在新账期按新成员集重新分摊，已出账期快照保持不可变。

## 8. 实际验证结论（2026-11-25 执行）

- 后端 `mvn -DskipTests package` 成功产出 `target/lakegov-backend-1.0.0.jar`；`mvn test` 集成测试 **11/11 通过**（含共享分摊 3 个测试类方法）；
- 前端 `npm run build` 成功（含新增 `CostShareView` chunk），`npm run preview` 静态服务 HTTP 200；
- `python3 scripts/verify_e2e.py` **80 项断言全部通过**，完整输出见 `docs/verify_e2e_output.txt`；
- RBAC：reviewer 只读账号 GET 返回 200、写操作返回 403；admin 全部操作可用；
- 关键测算实测（共享分摊）：账单总额 **¥19.00**；引用权重路线 **A ¥12.90 / B ¥6.10**（O1 按 3:1 分摊 7.50/2.50），Shapley 路线 **A ¥10.40 / B ¥8.60**（O1 平均边际各 5.00），两路线 `reconciled=true`；字节时长账 3 对象×30 天=90 行、O1 月费精确 ¥10.00；撤销 B 末次引用后 2026-11 不变、2026-12 O1 全归 A（¥10.00），恢复引用后新账期回到 7.50/2.50；
- 关键测算实测（恢复路线）：单次按需恢复 **¥17.145**（取回 12.165 + 计算 4.98）、恢复包月费 **¥5.40**、盈亏平衡 **3.83 次/年**；年 1 次预约分层更省（¥17.15 vs ¥65.01），月 1 次恢复包更省（¥67.32 vs ¥205.74）；
- 本容器无 docker 守护进程，Dockerfile/Compose 已交付但未在本机构建，已用预装 JDK 25 / Node 22 / PostgreSQL 18 完成等价验证。
